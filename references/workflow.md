# origami-blue — production workflow (commands and file formats)

`$OB` = this skill's folder (`~/.claude/skills/origami-blue`). All scripts are tested on the creator's
M2 MacBook (8 GB). Run Python scripts with a venv that has numpy, pillow, scipy (e.g. reuse
`<video-set>/work/.venv`, or `python3 -m venv ~/.cache/ob-venv && ~/.cache/ob-venv/bin/pip install numpy pillow scipy`).
The camera exporter needs node + gsap (already installed in `$OB/scripts/node`; if missing: `cd $OB/scripts/node && npm install`).

## 2. Phase 1 — prep and transcript

```bash
bash $OB/scripts/prep.sh <video-set>/work-oct12 a=<video-set>/oct-12/FIRST.MP4 b=<video-set>/oct-12/SECOND.MP4
```
Produces `a-sdr.mp4` (SDR, mirrored later in the pipeline), `a.transcript.json` (word list `{text,start,end}`).
If a transcript says "cancelled", re-run (first model load sometimes cancels). Print the transcript with word
timings and read it fully; you'll need exact word starts for every entrance.

`ffprobe` the duration → `DUR`; frames `N = round(DUR*30)`. (You can plan beats from a transcript alone, but
`DUR`, `clear.json` and the cards need the real footage.)

## 3. Phase 2 — authoring

```bash
bash $OB/scripts/new_episode.sh <video-set>/videos/ep07-full ep07-full
```
First write the **beat sheet** (`<work>/<key>-beats.md`, your design document; the creator never needs to
read it, the cards are what they review). One table, one row per beat or speaker-only breath:

| # | window (s) | spoken line | visual | layer (behind/front/page) | yellow hero (or none) | motion keyed to words (word @ time) | camera | SFX |

followed by: the turn in one sentence, the callbacks (which beat returns where, resolved how), the cutaway, the
3 ghost words, open questions for the creator (spellings, mishearings, episode order). Then derive the files.

Then write (start from the closest example in `$OB/examples/`):

- `parts/body.html` — groups as `.layer.behind.clip` / `.layer.front.clip` with `data-start` / `data-duration`;
  add each top-area group id to the zone-transform CSS at the top. Tile number `ep. 07`.
- `parts/script.js` — keep the helper block and the marker `const q = (s) =>` (fx.js is injected there). One
  block per beat. Set `DUR`. Update tile/crore/CTA times to the transcript words; set the caption cut at the
  tile start (`if (start < 6.5 && end > 6.5)`).
- `camera.cjs` — keys `[t, full(z), dur, ease]` (see style-system §7).
- `<key>-cards.json` — the card spec: one entry per beat peak:
  `{"t": 33.3, "title": "The reframe", "line": "…the spoken line…", "visual": "…what's on screen…", "motion": "…what animates on which word…"}`
  (13–17 cards for 2 minutes; include hook, tile, ₹1 crore, every beat peak, each callback, CTA).
- `<key>-clear.json` — `[[t0, t1, C], …]` screen-y the head top must stay below per beat. For front/text beats:
  bottom of that beat's lowest text + ~20 (`screen = 1.06*y + 45` for zone groups). For behind diagrams the
  hair may overlap the lower part (that's the chroma depth), so use the bottom of the part that must stay
  readable (labels, the key state), not the floor line. Typical 540–670; above ~680 forces big zooms. Full-page
  cutaways and the tile need no entry.
- `<key>-wins.json` — `[[t0, t1], …]` every time window where a `.behind` element is visible: from the clip's
  first visible moment to its exit end (ghost words included). Merge windows that overlap or are < 1s apart;
  skip stretches where a long behind clip is fully hidden (opacity 0 between appearances). The subject
  cut-out is produced only for these windows.
- `TILE` (in `ep07.env`): `"<tile clip start> <wipe start>"` — words spoken while the tile fully covers the
  screen get no caption; words after the wipe starts are captioned.
- `<key>-cues.json` — SFX `[[t, "whoosh|pop|impact|thud|tick", vol], …]` on the same words as the visuals.
- `ep07.env` — from `scripts/episode.env.example` (PY, WORK, PROJ, K, EP, DUR, TILE, KEYWORDS, TRANSCRIPT).

Assemble + lint as you go:
```bash
$PY $OB/scripts/assemble.py <proj> <work>/a.transcript.json <DUR> <tile0> <tile1> "<kw|kw>" && (cd <proj> && npx hyperframes@0.8.134 lint)
```
0 errors required. Known harmless warnings: `nested_structure_needs_subcomposition`, `composition_file_too_large`,
`timeline_track_too_dense`.

**Quick preview while authoring** (no footage, no key, no plates; ~10 s for a few frames, ~1 min for a dozen):
```bash
bash $OB/scripts/quick.sh ep07.env              # assemble, then snapshot every card time
bash $OB/scripts/quick.sh ep07.env 12.4,33.3    # just these seconds
```
→ `<proj>/cards/quick/frames/frame-NN-at-Ts.png` + `contact-sheet*.jpg` (split in pages past ~12 frames): all layers (behind, front, captions) on a
mid-grey ground. Use it to check wraps, overlaps, safe zones, and what is already visible a moment *before* an
entrance word (the classic bug: snapshot at word − 0.2 s). It can't show key quality or head clearance; those
need the cards.

## 4. Phase 3 — cards

1. **Chroma-key zones (once per room/framing).** Run `bash $OB/scripts/cards.sh ep07.env`; the first time it
   stops and writes `plates/a-grid.png` (median plate with a 20px grid, labels every 100px, half-res mirrored
   coordinates). Add to `<work>/zones.json`:
   ```json
   {"a": {"zone": [30, 10, 510, 495], "props": [[330, 315, 442, 456], [148, 288, 212, 432]]}}
   ```
   `zone` = area the key may cut (full width, top down to just above the chair backrest); `props` = boxes
   around static objects touching the hair that look skin-coloured (leaning book stack, lamp). Same room + same
   framing → copy the previous entry.
2. Re-run `bash $OB/scripts/cards.sh ep07.env`. It assembles, lints, exports the camera, builds the clean
   plates, renders card layers (behind/front on black+white for exact alpha), composites each card on the real
   frame with the keyed subject, and writes `cards/overview.jpg`, `cards/boards/epNN-board-K.jpg` (2×2 cards with
   notes) and `cards/keytest.jpg` (green = removed by the key).
3. Inspect: open overview + zoom crops of dense cards. Fix wraps, overlaps, elements visible early, key
   problems (book bits glued to hair → adjust props; hair notches → props too wide). Re-run (≈2–3 min).
4. Send overview + boards to the creator (SendUserFile), with the open questions. Wait for approval.

## 5. Phase 4 — full draft render

```bash
nohup caffeinate -dimsu bash $OB/scripts/render.sh <work>/ep07.env > <work>/render-ep07.log 2>&1 &
```
Steps and typical time for a 2:15 clip (8 GB Mac, nothing else heavy running):

| step | output | time |
|---|---|---|
| cut-out (`remove-background`) | `a-alpha.mp4` | 15–25 min |
| book key (`keyvideo.py`, 2 procs) | `a-keyed.mp4`, `a-headtop.json` | 15–20 min |
| adaptive camera (`adapt.py`) | `a-cam.json` | seconds |
| footage prep (`plates.py`, 3 slices) | `media/base.mp4`, `media/subj-XX.webm` | 20–30 min |
| audio (`mix.py`) | `media/mix.m4a` | seconds |
| graphics passes (`passes.sh` behind/front/caps) | `renders/behind|front|caps/*.png` | 4 + 25 + 4 min |
| composite (`fastcomp.py`) + mux | `renders/epNN-draft.mp4` | 10–15 min |
| preview + QA sheet | `-preview.mp4` (< 30 MB), `epNN-sheet.jpg` | 1 min |

Two episodes: run the second episode's cut-out while the first one's later steps run, but never two Chrome
renders at once. The script is resumable: re-run the same command after any crash/power cut.

## 6. Phase 5 — QA checklist

- `ffprobe`: video frames = N, duration = DUR, audio present; loudness ≈ −14 LUFS
  (`ffmpeg -i draft.mp4 -af ebur128 -f null -`).
- `renders/epNN-sheet.jpg` matches the approved cards beat by beat.
- Grab frames 0.3–0.5s *before* every pop/entrance: nothing should be visible early.
- Captions never collide with page headlines or rows; never under the right rail below y 1156.
- Chroma beats: hair edge clean over ghost words/diagrams; no book bits; no notches.
- Send `epNN-draft-preview.mp4` (phone) + the full-res path.

### Add to the HyperFrames desktop app
The creator keeps every episode in the HyperFrames desktop app, named `Business Ep NN - <Short Topic>`. Set
`APP_NAME` in the env file and `render.sh` does it, or run
`bash $OB/scripts/to_app.sh "Business Ep 07 - Views vs Trust" <proj> <work>/a-cam.json <work>/a-wins.json`.
It makes `videos/studio/<App Name>/`, a viewing copy whose `index.html` is the complete edit (base footage +
subject clips + graphics + captions + `mix.m4a`, via `direct.py`) with `fonts/` and `media/` linked to the
project, then `hyperframes open` registers it. Notes:
- The app stamps editor ids into the composition it opens and keeps history there, which is why it gets a
  copy: the project's own `index.html` stays the pipeline's graphics-only input.
- Edits made in the app live in the studio copy; carry anything worth keeping back into `parts/` by hand.
- Use the app to watch, scrub and tweak. Full-length renders go through `render.sh`, since a one-shot render
  of the complete edit hangs on this Mac (render-pipeline.md).
- No rename command exists. A project opened through a folder symlink is named after the real folder, so
  always open the named studio folder.

## 7. Phase 6 — fast revisions

Edit `parts/*`, then for each changed time window:
```bash
$PY $OB/scripts/assemble.py <proj> <transcript> <DUR> <tile0> <tile1> "<kw>"     # graphics-only index
$PY $OB/scripts/segpass.py <proj> front 29.7 33.9          # [check] first to verify alignment (diff 0.0)
```
`segpass.py` time-shifts a copy of the composition (re-timed clips + `tl.tweenFromTo(T0,T1)`), renders just that
window of one pass and splices the frames in place (frame-exact). Then recomposite (`fastcomp.py` + mux, or
re-run `render.sh` after deleting the draft). Changing behind-layer windows also needs updated `wins.json` and
plates for the new windows.

## 8. Script reference

| script | role |
|---|---|
| `prep.sh` | HDR→SDR + transcript per clip |
| `new_episode.sh` | project from template |
| `assemble.py` | style + fx + body + captions + script → `index.html` (keywords, tile cut, word fixes) |
| `node/camexport.js` | camera.cjs → per-frame `[s,dx,dy,p]` |
| `adapt.py` | head-top clearance + caption offset → `cam.json` rows `[s,dx,dy,p,capdy,headtop_screen]` |
| `plate.py` / `modeplate.py` / `propplate.py` / `plategrid.py` | clean plates for the chroma key |
| `keyer.py` / `keyvideo.py` / `matte_clean.py` / `keytest.py` | subject key (ML matte × clean-plate difference, head prior) |
| `quick.sh` | graphics-only snapshots on grey + contact sheet while authoring (no footage/key) |
| `get_sfx.sh` | fills `assets/template/sfx/` with the five cue sounds if they're missing (fresh install) |
| `cardlayers.sh` / `cards.py` / `boards.py` | design cards |
| `plates.py` | screen-space footage: `base.mp4` + subject clips |
| `passes.sh` (in project) | graphics-only HyperFrames png passes |
| `fastcomp.py` | composite passes over base + subject |
| `mix.py` | voice + SFX + loudnorm |
| `segpass.py` | re-render a time window of one pass |
| `sheet.py` | contact sheet at card times |
| `cards.sh` / `render.sh` | orchestrators (episode.env) |
| `to_app.sh` / `direct.py` | complete-edit copy of an episode registered in the HyperFrames desktop app |
